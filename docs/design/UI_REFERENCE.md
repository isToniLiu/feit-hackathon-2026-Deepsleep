# CyberStage — 前端UI参考清单

> 对外产品名为 **CyberStage**，项目/仓库代号为 **DDL Lockdown**，核心案件为 **IR-247**。本文件记录当前视觉方向和后续参考点；当前实现状态以 [`docs/product/PRD.md`](../product/PRD.md) 第10节为准。
> 用途：找到的截图/链接直接丢进团队的FigJam白板，每张图配一句"喜欢这个的哪个点"，方便开发那边直接抄具体的处理方式，而不是抄一整套设计系统。
> 不用追求"找到一模一样的产品"，重点是收集**具体的交互/视觉处理细节**，比如"这个弹窗的阴影和圆角"、"这个卡片的信息层级"，而不是整站截图。

## 当前视觉决策（2026-09-30）

本项目正式采用“复古现代平面设计外壳 + 中央 ARG 模拟浏览器”的双层视觉方向。

### 外层产品页面

- 背景以暖白、米白、浅灰为主，保持安静、克制和充足留白。
- 使用强烈的编辑型衬线标题，搭配清晰的中性无衬线正文。
- 通过排版、细边框、规则线和少量圆角建立设计感，不依赖科技光效或赛博装饰。
- 首页、角色选择页、岗位工作台和结局页都以极简平面设计为基准。
- 外层页面尽量不使用大面积彩色，避免喧宾夺主。

### 中央 ARG 模拟浏览器

- 浏览器是产品的主要视觉焦点和核心调查现场。
- 浏览器内部可以使用更丰富的颜色：蓝、黄、红、紫和少量青绿色，用于系统状态、警告、风险和证据强调。
- 真实感主要来自标签页、地址栏、域名、时间戳、内部系统、文件元数据、状态页、聊天记录和可交叉验证的线索关系。
- 浏览器内部可以模拟不同企业系统的视觉差异，但必须保持同一家公司、同一案件和同一时间线的可信关系。
- 不使用霓虹、粒子、发光 HUD、赛博朋克背景或装饰性扫描线。

### 角色选择页

角色不再使用原有 AI 生成角色图片。角色卡可以使用统一风格的极简抽象线稿人像，用于突出岗位特性，但人像只是视觉锚点，不替代岗位信息，也不应成为角色立绘。

- Priya：安静、观察型的侧脸线稿，使用少量蓝色强调。
- Marcus：更有动作感和角度的线稿，使用少量黄色强调。
- Aiko：稳定、平衡、几何感更强的线稿，使用少量珊瑚红强调。
- 线稿必须放在独立的视觉区域内，和姓名、岗位、描述保持明确间距，不能与文字重叠。
- 不使用写实头像、3D 角色、AI 肖像、全身人物或高细节插画。

## 去哪找（优先级从高到低）

1. **Mobbin**（mobbin.com）——真实上线App/网页的截图库，按"模态框""空状态""卡片"这类具体UI模式搜索，比Dribbble更贴近真实可实现的效果
2. **真实产品官网/直接登录试用**——很多产品截图比设计稿更可信，因为是真的做出来跑起来的效果
3. **Dribbble / Behance**——搜具体关键词（如"incident dashboard"、"security app"），适合找配色/氛围灵感，但要注意很多Dribbble作品华而不实、不好实现，别照抄太复杂的
4. Google图片直接搜英文关键词（见下面每个模块后面的建议关键词）

## 按产品的6个模块分别找

### ① 整体氛围：复古现代的编辑式产品外壳
- 参考对象：Brilliant、Notion、Linear 的留白与信息层级，以及高质量报告/编辑排版的细线和规则感
- 搜索关键词：`editorial SaaS landing page`、`minimal flat design interface`、`typography driven product page`
- 重点看：外层页面要冷静、克制、有平面设计感；紧张感和颜色主要交给中央模拟浏览器，不在外壳上堆叠赛博效果

### ② 仪表盘首页 + 课程/任务卡片（EduFlow是Canvas类产品的自我认知）
- 参考对象：Canvas LMS、Google Classroom、Notion的"今日待办"卡片
- 搜索关键词：`LMS dashboard course card`、`assignment card UI`
- 重点看：卡片里信息怎么分层（标题/截止时间/状态标签怎么排布），不用管颜色，我们自己的品牌色不一样

### ③ 团队聊天/事故频道（篇章②"可疑文件"场景要用到）
- 参考对象：Slack、Discord、Microsoft Teams的频道消息界面
- 搜索关键词：`slack message bubble UI`、`chat attachment file card`
- 重点看：一条消息+一个文件附件是怎么排版的，尤其是"文件名+图标"这个小卡片的样式

### ④ 弹窗/模态框（登录过期、账号锁定这两个攻击场景的核心UI）
- 参考对象：任意SaaS产品的"重新登录""身份验证"弹窗，或者干脆搜"phishing simulation"类安全培训产品截图
- 搜索关键词：`login modal UI`、`verification modal design`、`security awareness training screenshot`（这个关键词能直接搜到KnowBe4/Proofpoint这类产品，跟我们的产品类型最像）
- 重点看：弹窗的阴影/圆角/图标处理，以及"这个弹窗看起来是不是有点不对劲"这种违和感要怎么用视觉语言表达出来

### ⑤ 角色入口与带教卡片（Priya/Marcus/Aiko三位岗位入口）
- 参考对象：Duolingo的角色引导页、游戏里的"NPC对话"界面、任何App的"认识一下你的教练/导师"引导页
- 搜索关键词：`character intro screen UI`、`onboarding mentor card`、`duolingo character screen`
- 当前决策：不再使用原有 AI 角色图片；角色卡使用极简抽象线稿人像作为岗位视觉锚点，岗位、系统访问和调查重点仍是主要信息。
- 重点看：线稿人像、姓名、岗位和任务说明如何形成清晰层级；线稿必须有独立空间，不得和文字重叠，也不要做成证件照或人物立绘。

### ⑥ 结局页（评分环+证据回顾+岗位小结）
- 参考对象：Duolingo的"本课完成"总结页、任意健身/学习App的"今日成果"页面
- 搜索关键词：`quiz result screen UI`、`score ring progress circle`、`lesson complete screen`
- 当前实现：环形评分、关键决策回顾、AI反馈、After Action Report、AI行动建议、当前岗位小结和其他岗位重开入口已完成。
- 重点看：环形进度条/分数、证据、行动、反馈和训练建议如何保持报告感，不要变成游戏胜利页。

## 一个可以直接抄的配色方向
外层页面采用暖白、米白、黑色和浅灰，颜色集中到中央模拟浏览器内部。浏览器内部使用蓝色表示系统与信息、黄色表示待确认、红色表示风险、紫色或青绿色表示辅助状态；颜色必须服务于线索和操作反馈，不用于制造赛博氛围，也不能让颜色直接泄露正确答案。
