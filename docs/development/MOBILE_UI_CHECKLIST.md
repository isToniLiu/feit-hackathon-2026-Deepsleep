# 移动端 UI 适配记录

> 当前版本只记录适配现状和验收标准，不代表已经完成移动端专项优化。后续修改移动端布局时，以本文件作为检查清单。

## 当前状态（2026-09-30 更新）

页面已经具备基础响应式布局，但目前主要按桌面端调查工作台设计，尚未完成手机浏览器上的完整人工验收。2026-09-30 对线上站点做过一次视口审计（内嵌浏览器的视口模拟，非真机），发现了下面“2026-09-30 线上审计结果”里的尺寸问题；此后仓库又有若干布局提交（视口高度约束、角色页适配桌面视口），审计结果需要在最新版本上复测后再确认。

已具备的响应式行为：

- 角色选择页在小屏幕下由三列卡片变为单列。
- 岗位工作台在小屏幕下由左右栏变为上下排列。
- 调查现场在小屏幕下由左右分栏变为“场景在上、聊天面板在下”。
- 聊天消息区在手机端限制最大高度并允许内部滚动。
- 顶部栏在小屏幕下隐藏部分次要状态文字，保留案件文件、状态和时间信息。
- 浏览器地址栏和聊天输入框使用 `min-w-0` / 弹性宽度，避免主要输入区域主动撑破页面。

## 目标测试尺寸

至少检查以下三种视口：

| 视口 | 用途 |
|---|---|
| 360 × 800 | 较窄的常见手机屏幕，检查文字换行和按钮拥挤 |
| 390 × 844 | 常见大屏手机，检查完整调查流程的滚动体验 |
| 768 × 1024 | 平板竖屏，检查手机布局和桌面双栏布局的切换边界 |

## 页面检查清单

### 角色选择页

- [ ] 三张角色卡在 360px 宽度下单列显示，没有横向滚动。
- [ ] 标题和说明文字自然换行，不遮挡角色图像或操作按钮。
- [ ] 每张卡片都能完整看到角色名称、岗位、调查重点和进入箭头。
- [ ] 背景图裁切后仍能保持文字区域的对比度。
- [ ] 卡片按钮可用单手触控，不需要精确点击很小的文字区域。

### 岗位调查工作台

- [ ] 任务列表、系统访问、证据重点、远程支援和“打开调查现场”按钮都能滚动看到。
- [ ] 页面内容不会因为 `overflow-hidden` 或视口高度不足而被裁切。
- [ ] 右侧信息栏在手机端变为纵向内容后，视觉层级仍然清晰。
- [ ] 三项任务文字不会造成卡片横向溢出。

### 调查现场

- [ ] 场景区域和聊天面板在手机端都可访问，不会出现其中一块完全不可滚动的情况。
- [ ] `CASE OBJECTIVES` 任务栏展开后不会遮挡主要调查按钮。
- [ ] 模拟浏览器的标签页、地址栏和页面内容在 360px 宽度下仍可操作。
- [ ] 调查动作按钮、确认按钮和返回/切换页面操作有足够触控面积。
- [ ] 做出决定后，当前场景仍然保留；玩家可以继续探索，再点击确认进入下一事件。
- [ ] 聊天消息过长时可以滚动，输入框和发送按钮不会被键盘遮挡。

### 顶部案件栏

- [ ] 案件编号、`CASE FILE` 按钮和时间在窄屏幕下不重叠。
- [ ] 打开 Evidence log 后，面板不会超出屏幕右侧。
- [ ] Evidence log 内容较多时可以完整阅读或滚动查看。

### 结局页

- [ ] 评分、决策回顾、AI反馈和岗位重开入口按纵向顺序完整显示。
- [ ] 长反馈文本不会撑破页面或导致横向滚动。
- [ ] 重新选择其他岗位的按钮在手机上容易点击。

## 2026-09-30 线上审计结果（待在最新版本复测）

测试视口：360×800、390×844、768×1024、1024×600、1366×768。所有视口下均没有整页横向滚动。

| 视口 | 问题 |
|---|---|
| 360×800 / 390×844 | 调查现场里模拟浏览器内容区实测约 335×9，几乎看不到场景；任务栏面板约 498px 高占满屏；场景标题被截成 `The admin session s…`，浏览器标签被截断 |
| 768×1024 | 分栏从 640px（`sm`）就启用，右栏只有约 151px 宽：聊天输入框约 43px 宽，消息一行一两个词，`0 / 3` 计数被裁掉 |
| 1024×600 | 右栏约 215px 宽，聊天消息区约 26px 高，`CASE OBJECTIVES` 标题被挤成竖排；弹窗出现双层滚动条 |
| 1366×768 | 基本可用，聊天消息区约 161px 高 |

其他问题：
- 顶部栏 `←`、`中文`、`Case file`、浏览器标签、`‹ › ↻ ×` 等点击目标小于 44px；全站有 10px 文字。
- 手机上顶部栏返回箭头、`CyberStage`、`中文` 几乎贴在一起；`Guide` 按钮在手机宽度下隐藏，没有替代入口。
- 切换页面时滚动位置不会重置（从角色页进入工作台会停在中段）。
- 疑似根因：分栏断点用 `sm`（`DecisionScreen.tsx`、`ChatPanel.tsx`、`BrowserShell.tsx`），右栏用固定 `w-1/4`、高度写死 `calc(100dvh-8rem)`，右栏没有最小宽度；外层 `overflow-hidden` 在小屏高度不足时会裁切内容。
- 建议方向：分栏断点改到 `lg`（≥1024px）并给右栏设最小宽度；768px 及以下改为上下堆叠、整页滚动，给场景保留最小高度；补齐点击热区；切换 screen 时 `scrollTo(0,0)`。

## 当前已知风险

1. `RoleSelectScreen` 和 `RoleWorkspaceScreen` 使用 `overflow-hidden`，在小屏幕高度不足时可能裁切底部内容。
2. 调查页在手机端需要同时容纳场景、任务栏和底部聊天面板，长内容可能造成滚动区域不直观。
3. 模拟浏览器内部页面虽然使用了弹性宽度，但尚未对 360px 宽度逐页人工确认。
4. 部分小字号标签和辅助操作尚未统一最小触控尺寸。
5. 当前没有移动端截图、真机测试记录或自动化视口测试。

## 后续验收标准

移动端专项优化完成后，应满足：

- 360px 宽度下主流程无横向滚动、无内容裁切。
- 角色选择 → 工作台 → 调查现场 → AI反馈 → 结局页可以完整走通。
- 调查现场的场景、任务栏、聊天面板和 Evidence log 都能访问并滚动。
- 任何关键按钮都能在手机触控下稳定点击。
- 至少保留一组 360 × 800 和一组 390 × 844 的人工验收截图或测试记录。
