# DEV_PLAN.md — 单机开发工作规划（功能与沉浸视觉并进）

> 背景变化：原 `docs/team/HANDBOOK.md` 第3.1节的5人角色分工（P1-P5并行）**暂停使用**——目前开发集中在这一台电脑上，不再按人头拆分并行任务包，而是**按依赖顺序单线推进**。2026-09-30 起，视觉规范以 `docs/design/UI_REFERENCE.md` 的最新决策为准：产品名为 **CyberStage**，项目/仓库代号仍为 **DDL Lockdown**，整体采用复古现代平面设计，重点强化模拟浏览器内部的ARG真实感。
>
> 目标不是"分给谁做"，而是记录当前产品从Walking Skeleton到ARG沉浸层的实际演进。核心状态机、场景调查、浏览器模拟、聊天反馈、动态任务栏、结局回顾和 CyberStage 视觉迁移已经跑通；旧暗色素材仅作历史记录，未完成项集中在参考卡、暂停、自适应分支、演示恢复和无障碍细节。

---

## 0. 总体策略

- **功能与沉浸视觉并进**：先保证状态机、调查动作、任务进度和AI反馈可验证，再统一角色入口、工作台、案件栏、聊天和结局页的 CyberStage 外壳；外层保持温和留白和编辑感，颜色与真实感主要集中在模拟浏览器内部。
- **先假数据，后真接口**：状态机和UI先用写死的假剧情文本/假AI反馈跑通交互，最后切换成真实LLM调用；当前已接入OpenAI并保留兜底，不再把“假AI阶段”描述成现状。
- **先Must，后Should/Could**：严格对照 `docs/product/PRD.md` 第4节 MoSCoW 排序推进，不要提前做Should项。
- **单线程开发顺序**：因为只有一台电脑在写代码，下面的阶段按**先后依赖关系**排列，不是并行任务包；做完一个阶段的验收点再进入下一个。
