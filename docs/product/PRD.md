## 1. 问题陈述

**赛道**：Untapped Talent Problem Statement —— **"Engineering the Future of Learning"**（Future Work主题）

**官方点题句**：*"What if learning was as engaging as the world's best games, as useful as a great mentor, and as personal as a one-to-one coach?"*

**官方挑战原句**：*"How might AI and emerging technologies create learning experiences that are smarter, more engaging and more impactful than ever before?"*

**官方引用数据**（WEF《Future of Jobs Report 2025》等）：到2030年39%从业者核心技能预计发生变化；全球约2/3劳动力将需要培训/再培训；77%雇主计划提升员工技能以更好地与AI协作。

**我们的理解转述**：AI正在快速改变职场所需技能，但传统学习方式（被动听课、一刀切的培训材料）跟不上这种变化速度，也无法针对每个学习者具体的思维方式给出反馈。我们要做的不是又一个"AI答题机"，而是让学习者在一个**高压、贴近真实生活的情景**里做出判断，AI像真人教练一样**读懂学习者自己的思考逻辑**并给出针对性反馈，而不是无论输入什么都套用同一套话术。

**产品形态**：情景决策式网络安全模拟游戏（对应官方焦点 D. Simulations and Virtual Environments 中列出的 "Cybersecurity simulations" 举例）。对外产品名为 **CyberStage**；**DDL Lockdown** 是项目/仓库代号，**IR-247** 是核心案件编号。

**视觉与品牌约束（2026-09-30）**：所有页面统一采用复古现代平面设计语言。外层使用温暖白/米白/浅灰、黑色文字、编辑式衬线标题、中性无衬线正文、细线分隔和克制圆角；不使用霓虹、HUD、发光或赛博朋克装饰。颜色和信息密度集中在中间的模拟浏览器内部，以浏览器 chrome、域名、时间戳、日志、内部系统和可交叉验证线索建立ARG真实感。角色页不再使用AI生成角色图，改用独立区域的极简抽象线稿人像，头像不得与文字重叠。详细规范见 [`UI_REFERENCE.md`](../design/UI_REFERENCE.md)。

### 1.1 完整产品介绍（逐屏体验）

> ✅ 本节为对齐 Genius Armoury **Module 1（威胁态势/岗位概览）+ Module 2（威胁类型/如何应对）**内容与"零基础/全年龄背景"用户画像后的**重构版**，取代此前"单一线性事故+2个同类决策点"的初版设计。

**世界观**：团队原创品牌 **Northlight Digital**——一家开发大学课程/作业管理平台的软件公司，其自研产品 **"EduFlow"**（形态类似Canvas，服务多所合作大学）今晚遭遇网络攻击导致服务异常，恰逢多所大学学生集中在午夜提交作业的流量高峰。玩家扮演实习生 **Jordan**，先从三个不同岗位中选择一个调查入口，进入同一份 IR-247 事故档案的不同系统与证据视角。完成一次调查后可以重开案件，体验另外两位同事的工作——**不是选择难度，而是选择你从哪里看见这场事故**，让Module 1的"网络安全岗位概览"自然融进叙事，而不是生硬讲课。

**逐屏流程（角色入口 + 单岗位篇章视角）**：

| # | 屏幕 | 玩家看到/做什么 | 对应Module内容 | AI在这一步做什么 |
|---|---|---|---|---|
| 1 | **调查入口选择** | 选择 Priya、Marcus 或 Aiko 负责的工作入口；三个入口都指向同一份 IR-247，但会打开不同系统、线索和调查任务 | **Module 1**：网络安全岗位概览 | — |
| 2 | **角色调查工作台** | 显示当前岗位、带教同事、系统访问范围、调查目标和3项任务；玩家明确自己要调查什么，再进入现场 | **Module 1**：岗位职责与工作场景 | — |
| 3 | **事故看板** | 问候"Jordan"，卡片显示"INCIDENT — EduFlow Service Disruption"；可选"30秒入门速览"或"跳过，我知道基本概念" | — | — |
| 4 | **威胁简报** | 一段非决策的背景说明：今晚的攻击者是谁、图什么（机会主义攻击者专挑高负载/人手紧张的时间点下手） | **Module 1**：威胁行为者态势 | — |
| 5 | **角色对应的调查篇章** | 进入所选岗位负责的系统：Priya核对异常登录、Marcus处理可疑文件、Aiko核查账号锁定流程；玩家通过模拟浏览器交叉调查、记录证据、拍板并写下理由，也可以选**🤔"我不确定"**求助。动作提交后现场不会自动卸载，玩家可继续探索；只有显式确认反馈才进入下一事件 | **Module 1**岗位概览 + **Module 2**威胁类型 | 读取理由文本和行动历史生成针对性反馈；若选"不确定"则用固定的简化解释帮助玩家继续调查 |
| 6 | **结局页** | 安全决策力评分环形图 + 当前调查的关键回顾 + 当前岗位视角小结，并提供直接重开其他岗位入口的按钮 | **Module 1**岗位概览的收尾 | 当前实现展示真实AI反馈和静态决策回顾；个性化行动卡仍是后续Should项 |

**贯穿全程的"零基础友好 / 神经多样性友好"机制**（任意屏幕都可用，不是流程的强制步骤）：
- **🧭 参考卡（规划中）**：计划在顶部栏加入按威胁类型分栏的"Northlight新人手册摘录"；当前版本尚未实现独立参考卡，现阶段由场景线索、聊天解释和任务栏提示承担支架作用
- **🫁 暂停按钮（规划中）**：计划允许玩家暂停倒计时；当前版本顶部时间是静态展示，没有可操作的暂停机制
- **🤔 "我不确定"选项**：每个决策点除了安全/危险两个选项，**新增第三个"求助"选项**，触发AI用最简单的话重新解释当前情境——不强迫零基础玩家在没读懂题目的情况下硬猜，是"求助"而非"认输"
- **术语后置原则**：所有专业术语（Credential Phishing / GRC 等）严禁作为理解题目的前提出现，只能在玩家做完决策后的反馈里"顺带附赠"；岗位介绍控制在1-2句、纯叙事调味，玩家完全不懂"Incident Responder"和"GRC"的区别也不影响做出判断

### 1.2 对应赛题要求

**官方明确要求AI帮助学习者做到的6件事**（官方原文）→ 产品设计对应：

| 官方要求 | 产品里的对应设计 |
|---|---|
| stay motivated（保持学习动力） | 事故叙事+即时动作解释+动态任务栏+评分环和可重玩的岗位入口带来代入感和成就感，而非被动听课 |
| practise and apply knowledge（练习并应用知识） | 每个决策点玩家必须真实做出选择、写下理由——"做中学"而非"听中学" |
| receive meaningful feedback（获得有意义的反馈） | AI读取玩家自己写的理由生成针对性回应，而非无论输入什么都套用同一段文案 |
| build confidence（建立信心） | 已实现的动态任务栏、可选提示、🤔求助和非羞辱性反馈文案降低"怕出错"的心理门槛；🫁暂停机制与🧭参考卡仍待实现 |
| collaborate with others（与他人协作） | 剧情里"联系团队Lead走内部渠道"本身就是在教正确的协作/上报行为 |
| achieve better learning outcomes（取得更好的学习成果） | 当前通过行动历史、证据记录、任务进度和针对性AI反馈让学习过程可回顾；AI自适应分支和结局行动清单仍是后续增强项 |

| 评分维度 | 产品如何满足 |

| 有效性 40% | demo现场评委自己就能玩一遍、亲眼看到AI针对自己打的字生成不同回应——效果即时可验证，不依赖"相信长期学习成果"这类难以证明的东西 |

## 2. 目标用户 & 核心痛点

**主画像：Genius Armoury网络安全学习者**（对应Untapped官方学习平台 learning.untappedme.com 实地调研）

| 维度 | 具体内容 |
|---|---|
| **身份/入口门槛** | 官方定位"For all ages and backgrounds"，**不要求任何网络安全先备知识**（"minimal or no prior knowledge"）；典型身份是学生、早期职业从业者，或认真考虑往网络安全方向发展的人 |
| **能力光谱** | Genius Armoury完整课程分7个模块，从Module 1-2的零门槛科普，一路爬升到Module 5的Python/Linux编程、Module 6-7的合规/AI前沿话题——**同一批用户里"纯好奇的路人"和"认真想转行学编程的人"并存**，不是单一水平群体 |
| **认知特征（官方"优势视角"框架）** | 官方原文强调"excellent memory, ability to see patterns, great attention to detail, ability to focus on a task for long periods, curious and inquisitive may have an advantage"——常见于神经多样性人群（ADHD超专注/自闭症模式识别）的认知优势，Genius Armoury本身是帮神经多样性人才进入网络安全职业的项目 |
| **广义人才生态** | Untapped官方"About Us"页明确其服务对象为四类"Untapped Talent Ecosystems"：**Neurodiverse（神经多样性）、Veterans（退伍军人）、First Nations（原住民）、Sports（运动员转型）** |
| **教学理念参照** | Untapped自有产品线"Team Enablement"是一套卡牌游戏，官方原话"bring inclusion, innovation, and wellness to life — **not through lectures, but through play**"——游戏化、非讲课式是其自身认可的方法论，与我们的产品形态天然同频 |
| **核心痛点** | 传统网络安全意识培训枯燥、被动、一刀切，对零基础/神经多样性学习者不友好（术语堆砌、时间压力大、犯错被羞辱），学完记不住、也不知道自己具体的判断误区在哪 |
| **我们的方案怎么解决** | 情景决策游戏还原真实压力场景，AI读取玩家**自己写下的判断理由与行动历史**给出针对性反馈；内容难度对标Module 1-2；术语后置、🤔求助选项、动态任务栏和可选提示确保**零基础也能独立上手**。🫁暂停机制和🧭外部化参考卡仍待实现 |

| 市面企业级安全意识培训工具（如模拟钓鱼演练类产品） | 成熟、有企业采购的商业验证 | 面向企业员工设计，场景/语气不贴近学生生活，反馈通常是固定模板文案 | 我们的场景专门针对学生"DDL"生活情境设计，且反馈基于玩家**自己输入的理由**动态生成，而非固定文案库 |

## 4. MVP 范围（MoSCoW）

> ⚠️ 角色入口重构后，产品不再要求一次运行连续完成三个决策点；玩家选择一个岗位，完成对应篇章，再从结局页重开另外两个入口。范围包含角色工作台、模拟浏览器、聊天支援、动态任务栏和三类场景，但参考卡/暂停/自适应分支等增强项仍可取舍。
>
> 🕗 **Day1晚上8点验收检查点**：到点无论Should做到哪一步，先停下来逐条核对下面Must的3个勾选项是否都能跑通。**Must全部达标才开始/继续做Should**；如果Must没达标，8点之后全员先补Must，不再新开Should任务。

**🔴 Must（demo必须有，没有就跑不通）**
- [x] 三个角色对应的场景化事故节点：Priya身份验证、Marcus可疑文件、Aiko账号锁定/验证；一次运行聚焦所选角色的一个篇章
- [x] 每个决策点后，玩家输入"选择理由"，AI据此生成个性化教练反馈（真实调用LLM API，而非固定文案）
- [x] 结局页：安全决策力评分 + 关键决策回顾

**🟡 Should（有更好，砍了不影响演示）**
- [x] **开场威胁简报**（Module 1威胁行为者态势内容）——screen和事故背景文案已接入
- [x] **篇章② 恶意文件/仿冒社工**（新增威胁类型，补齐Module 2"威胁类型"的广度覆盖；已接入可调查的内部值班群文件场景）
- [x] **🧭 参考卡升级为按威胁类型分栏**（顶部参考卡按身份与访问、可疑文件、账号恢复提供三组判断框架）——外部化决策框架，呼应神经多样性友好设计
- [ ] **🫁 暂停机制**（决策弹窗内可暂停倒计时，第一次弹窗时就足够显眼）——把叙事紧迫感和玩家实际压力解耦
- [x] **🤔 "我不确定"选项**：每个决策点新增第三个求助选项，触发即时简化解释（目前是`story.fallback.unsure`固定文案，非LLM生成）——不算拍板，玩家还能回场景继续操作；保证零基础玩家能独立上手，不强迫硬猜
- [ ] **AI自适应分支**：AI读取玩家理由后判断其判断力强弱，据此从预写的分支变体中选择后续走向
- [~] **结局页AI生成个性化行动卡 + "今晚体验过的岗位"小结**："今晚体验过的岗位"小结已做（列出三位导师）；AI生成的个性化行动卡还没做，目前是静态决策回顾
- [ ] 沉浸感细节打磨（倒计时、贴近真实LMS/运维后台的UI等）
- [x] LLM调用失败时的预设文案兜底机制（保证现场demo不因网络问题卡住）——已实测验证（无效Key/网络失败均正确降级）
- [x] **ARG沉浸层**：案件编号、可展开的Evidence log、跨篇章线索回收，以及安全/危险选择对后续事故状态的影响
- [x] **现场持续探索与动态任务栏**：拍板和AI反馈后仍保留当前场景；`CASE OBJECTIVES`显示3项任务、进度、当前目标和可选提示，只有显式确认才进入下一事件

## 5. Walking Skeleton（走查流程）

用户打开页面 → 选择一个岗位调查入口（Priya / Marcus / Aiko）→ 查看角色调查工作台（岗位、系统、目标、3项任务）→ 进入模拟场景（Northlight Digital公司EduFlow平台遭遇攻击）→ 威胁简报 → 进入该岗位负责的调查篇章（在模拟浏览器里查线索、更新证据和任务进度，可选"我不确定"求助）→ 做出动作并输入理由 → 动作与AI反馈留在当前现场，玩家继续探索或补证据 → 点击明确的确认按钮后进入结局页 → 查看安全决策力评分、真实AI反馈和当前岗位视角小结 → 直接重开案件，体验另外两个入口

## 6. 验收标准 / Definition of Done

- 用户从打开页面到看到最终结局评分，能在3-5分钟内完整走完全流程，无卡死/白屏
- 每次输入理由后，AI反馈应在合理时间内（目标5秒内）返回，且内容明显反映用户输入的具体文字内容（同一个选项，不同的理由应得到不同的回应，而非固定模板）
- 若LLM调用失败/超时，页面自动切换到预设兜底文案，流程不中断
- **零基础可用性**：一个完全没听说过网络安全概念的人，不看任何外部说明，从打开页面到玩完结局页，应该能独立理解每一步在问什么、为什么这样选是对的——如果中途需要暂停去查资料才能继续，说明设计还不够零门槛
- **探索连续性**：玩家做出拍板动作或收到AI反馈后，不应被自动跳离当前现场；必须通过明确的确认操作才进入下一事件，场景内可继续查看页面、线索和案件档案
- **任务可见性**：角色的3项调查任务应在工作台和现场任务栏保持一致；任务栏可以提示方向，但不能直接泄露安全/危险答案
